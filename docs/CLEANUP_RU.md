# Безопасная очистка Repka: чек-лист

Документ описывает подготовку очистки, а не разрешение на удаление.
Удалять можно только конкретные пути после отдельного подтверждения
владельца и проверки резервной копии.

Актуальное руководство по установке: [HANDOVER_RU.md](HANDOVER_RU.md).

## 1. Текущее состояние на 28.10.2026

- Служба `usv-panel.service` активна, `WorkingDirectory=/root/usv_record`.
- Drop-in `TimeoutStopSec=3720s` применён.
- `/dev/root`: 58G, занято 51G, свободно 4,3G (93%).
- Порог запуска записи: 4096 MiB свободно; критический резерв: 1024 MiB.
- Последняя известная сессия: `/root/recordings/20261025_091848_098433`.

Свободного места недостаточно для длительной записи. Сначала очистка,
затем контрольная запись.

## 2. Что нельзя удалять

- `/root/usv_record` — действующий код службы.
- `/root/recorder/venv-pyav14` — интерпретатор из `ExecStart`.
- `/etc/systemd/system/usv-panel.service` и каталог `.d`.
- Настройки сети, токен панели, SSH-ключи, `.env` и другие секреты.
- Любые сессии и архивы, полнота резервной копии которых не проверена.
- Каталоги по маскам: `rm -rf /root/recorder*` и подобные команды запрещены.

## 3. Кандидаты на удаление

Малые каталоги и файлы, не используемые службой:

| Путь | Размер по инвентаризации | Назначение |
| --- | ---: | --- |
| `/root/recorder-profile-test-20261025-080008` | 548K | прежняя рабочая копия |
| `/root/recorder-profile-test-20261025-080008.before-live-20261025-084057` | 416K | снимок перед живым запуском |
| `/root/usv-handover-source-20261028.txt` | 296K | исходный текст подготовки передачи |
| `/root/usv-stop-timeout-backup-20261025-090726` | 112K | резервная копия перед изменением таймаутов |
| `/root/camera_tests` | 112K | старые эксперименты |

Внутри `/root/recorder` отдельно проверяются:

- `backup_before_dual_session_20261024_190336/`;
- `backup_before_panel_20261024_211535/`;
- `__pycache__/`;
- старые экспериментальные скрипты (`*_test.py`, `record_dual*.py` и другие).

`/root/recorder` целиком не удалять: внутри находится `venv-pyav14`.

Основной объём занимают видеоданные. Удаление кода освободит менее 2 MiB;
для записи нужно освободить место в `/root/recordings` после проверки копии.

## 4. Обязательная проверка перед удалением записей

### 4.1. Архив

На Repka и на внешнем носителе вычислить SHA-256 одного и того же архива:

```text
sha256sum /root/usv-before-clean-20261028.tar.gz
```

Значения должны совпасть. Если архив на внешнем диске переименован,
сравнивать именно его содержимое, а не имя.

### 4.2. Каталог сессии

На Repka:

```text
cd /root/recordings/20261025_091848_098433
find . -type f -printf '%P\t%s\n' | sort > /root/session-files-repka.txt
find . -type f -print0 | sort -z | xargs -0 sha256sum > /root/session-sha256-repka.txt
```

На внешнем носителе выполнить аналогичные команды в каталоге копии.
Сравнить:

1. список относительных путей;
2. размеры;
3. SHA-256 каждого файла;
4. количество файлов.

Совпадение только имён или успешное воспроизведение видео недостаточно.
Только после совпадения всех пунктов можно согласовывать удаление
`/root/recordings/20261025_091848_098433`.

## 5. Порядок очистки

1. Убедиться, что панель в состоянии `idle`, запись не идёт.
2. При необходимости остановить службу:
   `systemctl stop usv-panel.service`.
3. Выполнить `df -h /root` и свежую инвентаризацию:
   `du -sh /root/recorder* /root/camera_tests /root/recordings`.
4. Проверить архив и каталог сессии по разделу 4.
5. Показать владельцу точный список путей и получить подтверждение.
6. Удалять только подтверждённые пути. Не объединять удаление с другими
   операциями и не использовать маски.
7. Запустить службу: `systemctl start usv-panel.service`.
8. Проверить `systemctl status usv-panel.service --no-pager -l` и `df -h /root`.

## 6. Проверка после очистки

1. Панель доступна на `http://<IP-Repka>:8099/`, токен принимается.
2. Контрольная запись 1280x720@30, dynamic=0, 30 секунд.
3. Во время записи работает просмотр, второго открытия камер нет.
4. После остановки обе камеры `verified`, wrapper завершился с кодом 0.
5. Повторно открывается просмотр после записи.
6. В `session_metadata.json` сохраняются `profile`, `requested_mode`,
   `negotiated_mode` и `measured_capture_fps`.

## 7. Откат

До подтверждения новой установки сохранять прежний каталог
`/root/recorder-profile-test-20261025-080008`. Если новая служба не прошла
проверку, остановить её, вернуть в unit прежний `WorkingDirectory` и
`ExecStart`, выполнить `systemctl daemon-reload` и запустить службу.
Не удалять прежний каталог до успешной контрольной записи.
