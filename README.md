# USV Record: запись видео с двух камер на Repka Pi

Комплект для записи видео с двух USB-камер на борту безэкипажного катера.
Запись запускается и останавливается кнопкой на веб-странице, файлы двух
камер сохраняются в одну общую сессию.

Репозиторий содержит Python-скрипты, а не устанавливаемый пакет. Код
рассчитан на Linux с V4L2; на Windows его можно читать и править, но
захват видео там не работает.

## 1. Состав установки

| Компонент | Значение |
| --- | --- |
| Плата | Repka Pi 4, 2 ГБ RAM, aarch64 |
| ОС | Linux 6.12.9, glibc 2.35 |
| Python | `/root/recorder/venv-pyav14/bin/python`, Python 3.10.12 |
| PyAV | 14.0.0 (единственная запись в `requirements-runtime.txt`) |
| Камеры | 2 × USB/UVC-камера, сенсор AR0234 Global Shutter |
| Устройства | `/dev/video2` — левая камера, `/dev/video4` — правая |
| Формат захвата | MJPEG (MJPG), без декодирования и повторного сжатия |
| Код установки | `/root/usv_record` |
| Записи | `/root/recordings` |
| Панель | `http://<IP-Repka>:8099/`, доступ по токену |
| Накопитель | системный раздел 58 ГБ; внешний диск используется для выгрузки |

Точные модели камер в документации не зафиксированы: указан только сенсор
AR0234 Global Shutter. Модель и серийные номера следует взять с маркировки
корпусов и внести в акт передачи.

Привязку `/dev/video2` и `/dev/video4` нельзя менять «для порядка»: номера
устройств зависят от порядка подключения USB. Проверять так:

```bash
v4l2-ctl --list-devices
ls -l /dev/video*
```

## 2. Что умеет

- Показывает обе камеры в браузере без остановки записи.
- Пишет обе камеры одновременно в один общий каталог сессии.
- Режет запись на сегменты MKV примерно по 10 секунд.
- Ведёт `frames.csv` с покадровым индексом и SHA-256 каждого пакета.
- Пишет `session_metadata.json` с профилем, режимом и результатом проверки.
- После остановки перечитывает сегменты и проверяет целостность: содержимое,
  хеши, PTS, ключевые кадры, количество пакетов и порядок индексов.
- Показывает статус `verified`, `needs_review` или `failed` раздельно по камерам.

Запись не начинается автоматически при загрузке: её всегда запускает
оператор кнопкой.

## 3. Быстрый старт для оператора

1. Включить питание, дождаться загрузки и появления установки в сети.
2. Узнать адрес: `hostname -I`.
3. Открыть в браузере ноутбука или телефона: `http://<IP-Repka>:8099/`.
4. Ввести токен панели. Он хранится в файле `/root/.config/usv-panel/token`
   и намеренно не печатается в журнал:

   ```bash
   cat /root/.config/usv-panel/token
   ```

5. Выбрать проверенный профиль `1280x720@30`, `exposure_dynamic_framerate=0`.
6. Нажать запись. Во время записи доступен просмотр.
7. Остановить запись кнопкой и дождаться результата по обеим камерам:
   успех — `verified` у левой и правой, код возврата wrapper `0`.

Стартовый профиль панели — `1280x720@60`. Для ответственной записи
использовать проверенный `1280x720@30`: он испытан на этой установке.

## 5. Автозапуск

Служба `usv-panel.service` включена в автозагрузку и работает от `root`.

| Что | Где |
| --- | --- |
| Unit | `/etc/systemd/system/usv-panel.service` |
| Drop-in с таймаутом | `/etc/systemd/system/usv-panel.service.d/20-verification-timeout.conf` |
| Рабочий каталог | `/root/usv_record` |
| Интерпретатор | `/root/recorder/venv-pyav14/bin/python` |

Проверка состояния:

```bash
systemctl status usv-panel.service --no-pager -l
systemctl is-enabled usv-panel.service
journalctl -u usv-panel.service -n 100 --no-pager
```

Управление:

```bash
systemctl restart usv-panel.service
systemctl stop usv-panel.service
```

`Restart=no`: после аварийного падения служба сама не поднимется, её нужно
запустить вручную. Это сделано намеренно, чтобы панель не начинала работу
незаметно для оператора.

Остановка службы не обрывает запись мгновенно: панель отправляет wrapper
SIGTERM и ждёт до 3660 секунд, wrapper даёт рекордерам до 3600 секунд на
корректное закрытие файлов и проверку. `TimeoutStopSec=3720s` в drop-in
задаёт общий предел systemd. Эти значения увеличивать или уменьшать только
осознанно: при коротком таймауте проверка не успеет завершиться и запись
останется в состоянии `needs_review`.

### Как поменять параметры автозапуска

Параметры запуска задаются в строке `ExecStart` файла
`/etc/systemd/system/usv-panel.service`. Порядок:

```bash
sudo nano /etc/systemd/system/usv-panel.service
sudo systemctl daemon-reload
sudo systemctl restart usv-panel.service
systemctl status usv-panel.service --no-pager -l
```

Типовые изменения:

| Задача | Что править |
| --- | --- |
| Другой порт | `--port 8099` в `ExecStart` |
| Другие устройства камер | `--device-left`, `--device-right` |
| Другой каталог записей | `--output-root` |
| Ограничить длительность записи | `--record-seconds` (0 — до остановки оператором) |
| Длина сегмента MKV | `--segment-seconds` |
| Порог свободного места | `--min-free-mib`, `--critical-free-mib` |
| Увеличить таймаут остановки | drop-in `TimeoutStopSec`, а также `--stop-wait-seconds` |
| Переменные окружения | строки `Environment=` в секции `[Service]` |

После правки unit обязательно `daemon-reload`, иначе systemd продолжит
работать со старой версией. Не запускать второй экземпляр панели вручную
поверх службы: сработает блокировка, но состояние станет неочевидным.

## 6. Параметры запуска

### 6.1. Панель `control_panel.py`

Эти параметры принимает код автозапуска. Значения по умолчанию указаны для
запуска без аргументов; в unit часть из них задана явно.

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--host` | `0.0.0.0` | адрес прослушивания |
| `--port` | `8088` | порт панели (в автозапуске используется `8099`) |
| `--fps` | значение модуля просмотра | частота кадров просмотра |
| `--max-clients` | значение модуля просмотра | предел одновременных клиентов |
| `--device-left` | `/dev/video2` | левая камера |
| `--device-right` | `/dev/video4` | правая камера |
| `--v4l2-ctl` | `v4l2-ctl` | путь к утилите настройки камеры |
| `--output-root` | `~/recordings` | корень сессий |
| `--record-seconds` | `0` | `0` — до остановки оператором |
| `--segment-seconds` | `10` | длина сегмента MKV |
| `--queue-frames` | `120` | предел очереди пакетов на камеру |
| `--queue-mib` | `32` | предел очереди по объёму, MiB |
| `--min-free-mib` | `4096` | ниже этого запись не стартует |
| `--critical-free-mib` | `1024` | ниже этого запись штатно останавливается |
| `--token-file` | `~/.config/usv-panel/token` | файл токена |
| `--record-lock-file` | `~/.cache/usv_record/record_dual.lock` | блокировка записи |
| `--panel-lock-file` | `~/.cache/usv_record/panel.lock` | блокировка второго экземпляра |
| `--stop-wait-seconds` | `3660` | ожидание wrapper при остановке |
| `--status-interval` | `1` | период обновления статуса, с |
| `--disk-interval` | `5` | период проверки места, с |
| `--ready-timeout` | `30` | ожидание готовности записи |
| `--preview-ready-timeout` | `15` | ожидание готовности просмотра |
| `--dual-script` | пусто | путь к wrapper, если он не рядом |
| `--fake-cameras` | выключено | тестовые JPEG вместо устройств |
| `--fake-capture-fps` | `60` | частота заглушки камер |
| `--no-lock` | выключено | не создавать lock-файлы |

### 6.2. Wrapper `record_dual_session.py`

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--output-root` | `~/recordings` | корень сессий |
| `--device-left`, `--device-right` | `/dev/video2`, `/dev/video4` | устройства |
| `--width`, `--height` | `1280`, `720` | размер MJPG-кадра |
| `--fps` | `60` | запрошенная частота |
| `--exposure-dynamic-framerate` | `0` | `0` — фиксированная частота, `1` — адаптивная |
| `--preview-root` | нет | приватный каталог кадров просмотра |
| `--seconds` | `35` | длительность, `0` — до остановки |
| `--segment-seconds` | `10` | длина сегмента |
| `--queue-frames`, `--queue-mib` | `120`, `32` | пределы очереди |

### 6.3. Рекордер одной камеры `record_camera_pyav_queue.py`

| Параметр | Смысл |
| --- | --- |
| `--device`, `--camera-id` | устройство и имя камеры |
| `--output-root` | корень для автосозданного каталога |
| `--output-dir` | точный каталог камеры; должен ещё не существовать |
| `--width`, `--height`, `--fps` | режим MJPG |
| `--exposure-dynamic-framerate` | должен совпасть с настройкой камеры |
| `--seconds`, `--segment-seconds` | длительность и сегментация |
| `--queue-frames`, `--queue-mib` | пределы очереди |
| `--preview-root` | каталог кадров просмотра |
| `--v4l2-ctl` | путь к утилите |

Прямой запуск рекордера читает `exposure_dynamic_framerate` с камеры и
отклоняет запуск при несовпадении. Wrapper сам устанавливает и проверяет
выбранное значение на обеих камерах.

### 6.4. Профили записи

Список режимов один для панели и wrapper (`record_profiles.py`):

| Режим | Статус |
| --- | --- |
| `1920x1080@60` | есть в списке, но не согласован к эксплуатации: не хватает пропускной способности USB |
| `1280x720@60` | стартовый профиль панели |
| `1280x720@30` | проверенный рабочий профиль |
| `800x600@60`, `800x600@30` | доступны |
| `640x480@60`, `640x480@30` | доступны |

Длительности в интерфейсе: 0, 10, 30, 300, 600, 1800, 3600 секунд, где `0`
означает «до остановки оператором».

## 7. Выходные данные

Каждая запись — отдельная сессия с временем UTC в имени:

```text
/root/recordings/<ГГГГММДД_ЧЧММСС_микросекунды>/
├── cam-left/
│   ├── cam_left_segment_0000.mkv
│   ├── cam_left_segment_0001.mkv
│   ├── frames.csv
│   └── session_metadata.json
├── cam-right/
│   └── ... те же файлы для правой камеры
├── cam-left.log
└── cam-right.log
```

- `cam_left_segment_%04d.mkv` — Matroska с исходными MJPG-пакетами без
  перекодирования. Временная шкала каждого сегмента начинается заново.
- `frames.csv` — индекс пакетов: `frame_id`, `segment_id`,
  `frame_in_segment`, `segment_file`, исходные `source_pts`/`source_dts`/
  `source_time_base`, монотонное время приёма `host_receive_monotonic_ns`,
  `requested_local_pts_ms`, `packet_size`, `packet_sha256`,
  `source_is_keyframe`. Полное описание полей — в `docs/HANDOVER_RU.md`.
- `session_metadata.json` — состояние (`starting`, `recording`, `verified`,
  `needs_review`, `failed`), профиль (`requested_mode`, `negotiated_mode`,
  `profile`, `measured_capture_fps`), параметры очереди и переполнений,
  сведения о писателе и результате проверки. Обновляется через временный
  файл с заменой, чтобы не оставить наполовину записанный JSON.
- `cam-left.log`, `cam-right.log` — вывод каждого рекордера, включая
  `Output:` и `Status:`.

`frame_id` сквозной в пределах сессии и не сбрасывается на границе сегментов.
`host_receive_*` — время приёма пакета на хосте, это не время экспозиции
камеры и не синхронизация двух камер между собой.

Коды завершения: рекордер возвращает `0` только при `verified`, иначе `1`;
wrapper возвращает `0`, только если оба рекордера вернули `0`.

## 8. Ограничения и меры предосторожности

- TLS не настроен: панель и токен передаются открыто, работать только в
  доверенной сети. Токен не публиковать и не пересылать в мессенджерах.
- Служба работает от `root` и слушает `0.0.0.0`. Не выставлять порт в
  интернет.
- Одновременно допускается только один экземпляр панели и одна запись.
- `1080p60` на этой установке не согласован: USB не резервирует нужную
  полосу, возможны пропуски.
- Запись требует не менее 4096 MiB свободного места. Следить за `df -h /root`.
- Переполнение очереди не скрывается: оно попадает в метаданные и влияет на
  итоговый статус.
- Перед отключением питания завершать запись и выключать ОС штатно.
- Воспроизведение файлов не заменяет проверку целостности: смотреть статус
  сессии, а не только картинку.

## 9. Диагностика

```bash
systemctl status usv-panel.service --no-pager -l
journalctl -u usv-panel.service -n 100 --no-pager
df -h /root
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video2 --get-ctrl=exposure_dynamic_framerate
v4l2-ctl -d /dev/video4 --get-ctrl=exposure_dynamic_framerate
```

Если панель открывается, но камеры нет: проверить, что устройства на месте и
не заняты другим процессом (`fuser -v /dev/video2 /dev/video4`). Если запись
завершилась со статусом `needs_review`, смотреть `cam-left.log`,
`cam-right.log` и `session_metadata.json`; не считать такую сессию
подтверждённой.
